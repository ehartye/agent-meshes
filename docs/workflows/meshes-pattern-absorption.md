The saved definition supports three modes:

- `track` records the supplied ledger as an immutable run snapshot. It dispatches zero workers and explicitly does not claim fresh verification or task completion.
- `audit` dispatches at most six source-only readers from the declared scout tasks, with one attempt each and read-only/no-network permissions. Preserve null/blocked slots. Frozen external source evidence must be present before offline review.
- `verify` dispatches the declared independent source verifier against the integrated snapshot. It does not reuse cached audit answers as fresh proof and never grants model/export, wiki or publication authority.

The maximum authored worker budget is six audit calls plus one fresh verifier call per revision, at most two explicit revisions: fourteen calls, one attempt each. Concurrency is two. Workers have no wall deadline; the originating coordinator owns manual controls and idle inspection. No automatic retries or plan-generated tasks are allowed.

Root's acceptance is separate: review all findings, map each lesson to actual shared helper/tests/guidance or an explicit unresolved gap, check all packaged paths and hashes, execute relevant CLI/package tests and typecheck, generate/open the mannequin demo, perform the paired skill comparison, and update/sync only the owned wiki paths. A source validator, schema-valid report, successful phase or empty missing list cannot substitute for those checks. Do not claim unimplemented runtime features are absorbed code or that editor evidence proves Fortnite gameplay.

4. Root changes shared interfaces, README and tests. There is one integration writer, so no two agents own the same file. Required early checkpoint: failing entrypoint/discovery test before the CLI routing change; run the existing focused gates after implementation.

6. Complete the owned wiki operation, update the ledger with exact evidence and leave the branch reviewable. Publishing/merging a plugin release is outside this request.

Task dependencies control readiness, not file transfer. This plan has no workflow writers; all source changes are integrated by root. If writers are added, each needs literal disjoint paths, authoritative retained capture identity and independent coordinator review before new snapshots reach successors.
