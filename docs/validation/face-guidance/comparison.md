# Face guidance comparison

This is one bounded planning comparison, not an asset-quality or time-saving
evaluation. Both respondents were launched in the same coordinator turn with no
history fork, no model override, no asset operations and a 650-word ceiling.

Scenario: adapt an existing robot GLB for R3F using blink/happy/surprised only,
preserving flat plates, custom topology and palette; diagnose a separately fitted
hood that clips during a turn. The baseline used the scenario alone. The guided
condition read the candidate mesh-rigging skill, face-design reference and native
build-identity reference. No automatic skill-trigger result is claimed.

The review criteria were preserving the brief, selecting a fitting motion
construction, avoiding an unnecessary universal facial profile, keeping project
design ownership explicit, separating build-time code from runtime assets,
checking intermediate/combined poses and explaining what transfers to the hood.
These criteria follow the owner's stated direction; this was not a blind rubric
or a statistically powered efficacy study.

Both plans retained the three requested expressions, flat plate construction,
palette, consumer inspection and intermediate-pose checks. Neither imposed ARKit
or hm08. The baseline gave concrete shape-key/topology and animation ownership
advice. The guided plan explicitly separated Python helpers at build time from
the GLB consumed by R3F, described project-owned design and pinned declared inputs,
and cautioned that declared dependencies are not an automatically complete Python
closure. Both transferred clearance/attachment/motion principles to the hood
without copying eyelid construction or one character's clearance dimensions.

This is evidence that the candidate can support the intended planning boundary
in one case. It does not establish a quality advantage, automatic activation,
successful engine import, generalized transfer, or reduced end-to-end authoring
time. A future different-brief artifact evaluation remains on the wiki roadmap.
